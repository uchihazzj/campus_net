## 一键网络诊断

打开“常用设置 → 网络诊断”，选择测试范围，再手动启动。默认是“状态诊断（只读）”：检查缓存地址与当前会话是否一致、查询认证服务器状态，分别测试绑定校园 IPv4 和默认路由的外网响应，再查询各账号的自服务在线 IP。即使自动外网探测或自动在线 IP 查询已关闭，手动状态诊断仍会执行这些检查，不修改开关。

**只读模式**不执行校园网登录、登出、失败恢复、重连或设备下线，不重新枚举网卡，也不写回认证状态或触发重连。自服务查询会按需使用配置账号登录独立的网页会话，只读在线列表；Cookie 仅在本轮内存中保留。正常监控仍按原有设置运行。

**完整功能测试会真实改变校园网会话并短暂断网。** 选择测试账号，点击“开始完整测试（会断网）”才会执行，启动或后台常驻不会自动运行。先验证测试账号和原在线账号的凭据可读、当前源地址与目标绑定一致，再向服务器确认原来的账号或离线状态；无法确定、原账号不在配置中或地址不一致时，提前停止，不发送登录/登出请求。

预检通过后先完成上述只读检查，再复用日常认证代码执行“登出 → 服务器确认离线 → 登录测试账号 → 服务器确认在线”；自动重连配置开启时，再登出模拟离线、确认后调用正常重连判定与自动登录核心、确认在线。关闭自动重连时明确跳过重连，不强行修改开关。**监控循环的定时调度和等待退避未在这项手动测试中强制触发**，报告会标注这项覆盖限制。

请求被门户接受与服务器确认成功分别记录，不能仅凭请求成功判测试通过。实际登录失败时，仍按现有策略清理所有已配置账号、重试一轮，报告记录清理顺序、结果、重试以及数字 `err_code` 等分类；不会故意提交错误密码制造故障。没有触发失败恢复时，该项显示跳过。

完整测试独占认证操作，避免用户按钮、后台监控或迟到状态查询插入步骤。结束、失败、取消或测试工作任务异常后，都尝试恢复测试前状态：原账号已经在线时只确认；否则先登出本次测试账号、确认离线，再以禁止账号切换捷径的登录核心恢复原账号，不因正常恢复而清理未选中的账号。原来离线则尝试登出测试账号并确认离线，之后还原运行时的重连暂停标记。取消表示“停止测试并恢复”，恢复阶段不接受再次取消。恢复失败或恢复任务本身异常单独标为 `restore_failed`，不会伪报成功；原来在线时保留原账号作为重连目标。网络故障、退出进程或服务器异常可能使恢复失败，不能保证不断网或必然恢复。

登录/登出或自动在线 IP 查询进行中时，按钮暂时禁用。诊断期间自动在线 IP 查询稍后执行，原有查询时间不被重置。只读阶段总预算为 90 秒，自服务最多检查前 16 个账号；超出预算或数量的部分明确标注。没有缓存地址时，只读模式跳过绑定检查，完整模式预检失败。完整测试最多接受 16 个配置账号，认证测试总预算 300 秒，单项动作 120 秒、确认 20 秒，另预留最多 150 秒尝试恢复。完整模式的真实认证仍按原有 DHCP/网卡绑定逻辑解析地址。两种模式都不修改代理、TUN、路由、网卡配置或开机自启。

只读模式每完成一项就自动保存。完整模式运行时只更新可复制的内存报告，先尝试恢复连接、释放认证锁，再后台保存最终或部分报告，防止磁盘写入卡顿延长断网；因此完整测试期间若直接退出或进程崩溃，尚未保存的内存结果可能丢失。网络失败或取消由测试流程处理时仍会在恢复尝试结束后保存结果。点击“复制诊断报告”即可提供给维护者分析，无需粘贴整个运行日志。文件固定为：

```text
C:\ProgramData\CampusNetClient\diagnostic-latest.txt
```

只保留最新一份，不上传到外部服务。保存失败时界面会提示，内存报告仍可复制。报告使用简洁的结构化英文，账号按配置顺序记为 `A1`、`A2`；保留结果、耗时、必要开关、状态分类及 IP 数量/匹配情况，不包含真实账号、完整 IP、网卡名称、密码、摘要、Cookie、请求参数、服务器原文或应用日志全文。编码问题记录为 `decode_failed`、`invalid_status_format` 等分类；`raw_utf8_valid`、`declared_charset`、`bom` 分别描述原始字节是否为合法 UTF-8、声明编码的受控分类及字节序标记，不将字节合法性等同于实际编码，避免把乱码和个人资料带入报告。

逐项结果用 `PASS`、`WARN`、`FAIL`、`SKIP` 表示，认证过程另外保留有上限的匿名 `EVENT`；末尾 `outcome=completed` 仅表示流程结束，需要同时看 `issues` 和 `skipped`。默认路由成功不证明校园 IPv4 或认证正常，源地址绑定也不保证绕过 Clash / Mihomo TUN。单个公共探测服务失败可能只是该目标不可达。开发验证只使用合成后端；真实会话测试由用户选择合适时间手动启动。

## 从哪里查看日志

先看界面“日志”，持久日志位于：

```text
C:\ProgramData\CampusNetClient\app.log
```

在 Windows PowerShell 5.1 中查看中文日志时使用 UTF-8：

```powershell
Get-Content C:\ProgramData\CampusNetClient\app.log -Encoding UTF8
```

反馈问题时，请说明触发步骤、界面状态和错误文字。不要公开真实账号、密码、配置文件或未脱敏日志。

## 登录与网络

| 现象 | 排查方法 |
| --- | --- |
| 登录失败 | 核对学校认证服务器、账号及运营商后缀、密码、校园网连接和网卡绑定；认证参数可能因学校而异 |
| 一直“等待确认” | 检查日志中的 `rad_user_info` 及 `[OnlineInfo]` 信息；请求成功仍需服务器确认会话 |
| 显示“状态未知” | 查询失败尚不足以确认掉线；检查认证服务器可达性及绑定网卡，避免反复手动登录 |
| 浏览器能上网，但客户端未确认在线 | TUN、代理或 IPv6 可达不等于校园 IPv4 账号已认证，以服务器会话查询为准 |
| 自动重连未触发 | 检查自动重连是否开启；手动登出会暂停本进程的重连，状态未知时也会等待 |
| 登出失败 | 保留的账号状态及登出入口可用于重试；先看具体错误，避免启动第二个实例反复操作 |
| 切换登录失败 | 检查目标账号凭据；单个登出失败不会跳过其余清理，后续登录仍可能因服务器或网络原因失败 |

正常在线时后台复用网卡缓存，手动刷新、离线迹象或会话变化会触发地址刷新。若 DHCP、唤醒或插拔网卡后显示异常，可先用“刷新状态”重新确认。

## 窗口与托盘

窗口关闭或最小化后默认收起到托盘。可点击托盘图标，或右键选择“显示窗口”；要彻底退出，使用托盘菜单。托盘不可用时关闭窗口会正常退出。

程序会恢复异常的已保存窗口尺寸。运行中若窗口缩成“小点”，再次点击托盘图标或“显示窗口”会检查实际客户区尺寸，按当前屏幕缩放恢复到最近记录的正常大小；没有有效记录时使用默认大小。最大化时也会修复异常的普通恢复尺寸，避免取消最大化后又变成小点。正常尺寸、窗口位置和最大化状态会保留，这个恢复过程不触发登录或重连。

若仍找不到窗口，先检查通知区域中是否已有实例；当前没有单实例保护，多开会让多个进程各自监控和重连，配置修改也可能互相覆盖。

## 自动更新

更新需要 exe 所在目录可写，并能访问 GitHub。检查更新先直连、失败后尝试环境变量代理；下载先尝试环境变量代理，再回退直连，当前不读取 Windows 系统代理设置。

| 现象 | 排查方法 |
| --- | --- |
| 检查或下载失败 | 查看错误信息，检查 GitHub 访问和环境变量代理；也可从 [Releases](https://github.com/uchihazzj/campus_net/releases) 手动下载 |
| 替换或重启失败 | 查看 exe 目录中的 `updater.log`，保留 `.exe.bak` 以便恢复 |
| 点击更新后程序退出但未重新出现 | 替换脚本可能未成功启动；先查看日志和备份，再手动启动客户端 |

替换脚本只等待发起更新的进程退出，替换或新程序启动失败时尝试恢复旧文件。当前仍有启动交接限制：程序创建 PowerShell 进程后即退出，尚未等待脚本就绪确认。更新文件检查包含大小及 PE 文件头，目前没有自动进行 SHA-256 或签名校验。

## 配置恢复

数据位于 `C:\ProgramData\CampusNetClient\`。如果配置被恢复或重置，检查日志、`config.json.bak` 和 `config.json.bad-<timestamp>`；不要在客户端运行时直接覆盖配置。更多规则见[配置备份与迁移](configuration.md#配置备份与迁移)。
